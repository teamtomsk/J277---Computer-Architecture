03 / Address or data?

Where it is ≠ what it is.

An address identifies a memory location. Its contents are the instruction or data stored there. PC and MAR hold addresses; MDR and ACC hold values.

The four register jobs

Address of the next instruction to fetch.

Address of the memory location being accessed.

Data or an instruction transferred to or from memory.

Temporary arithmetic and logic results.

A register is a small, very fast storage location inside the CPU. A register’s role determines what its bits represent.

Stored-program concept: in Von Neumann architecture, instructions and data share the same main memory. An address does not itself say whether its contents are an instruction or data; the program’s use of that location matters.

What do LOAD, ADD, SUB and STORE mean?

LOAD #8: put the literal value 8 in ACC. LOAD 10: read the value at address 10 into ACC. ADD #4: add 4. SUB 205: subtract the contents of address 205. STORE 11: copy ACC into address 11. HALT: stop this demo program.

These readable teaching instructions are not a real processor’s machine code. You do not need to memorise them for this lesson.

What to remember

Fetch: get the next instruction from memory.

Decode: the control unit interprets the instruction.

Execute: carry it out, using the relevant components.

06 / Cache lab

Avoid the slower trip to RAM.

Cache holds copies of instructions and data the CPU may need again. A cache hit means the requested item is already there. A miss means getting it from main memory.

Cache contents

0cache hits
0cache misses
0model time units
0without cache, same requests

Teaching model: a hit costs 1 made-up time unit; a miss costs 5. The least recently used item is replaced when full. This illustrates reuse, not real timing or a promise of speed-up.

What is stored where?

Registers: tiny working locations for immediate CPU operations.

Cache: a small, fast store of copies for quick access.

RAM: the larger main memory holding running programs and data.

Registers are typically faster to access than cache, and cache faster than RAM. None replaces long-term secondary storage.

Try changing one thing

Run repeated requests with 2 cache items, then 4. Does a larger cache help this pattern?

Now try addresses that are each requested only once. A bigger cache cannot create reuse that is not there.

That is why “more cache always makes everything faster” is too strong.

Looking ahead: CPU performance and embedded systems

These are the next J277 subtopics. Clock speed is cycles per second, not necessarily instructions per second. More cores can help work that can run in parallel; they do not automatically double every program’s speed.

An embedded system is a computer system with a dedicated function within a larger device—for example a washing-machine controller. A general-purpose smartphone is not, by itself, a good example of a dedicated-purpose system.
