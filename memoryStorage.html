What happened during startup?

The CPU runs startup instructions held in ROM. These begin the process of loading the operating system from secondary storage into RAM. Opening an app and a file also loads working copies into RAM.

02 / Different jobs · 6 minutes

Working now or keeping for later?

Primary storage includes RAM and ROM. Primary does not always mean volatile: ROM keeps its contents. Cache is a quick link back to your CPU lessons.

RAM

Random Access Memory

Holds the operating system, programs and data currently in use.

Read and write · fast working space · volatile

ROM

Read Only Memory

Holds instructions needed to start the computer.

Read in normal use · non-volatile

Cache

Small, very fast memory

In or close to the CPU; holds copies of data and instructions likely to be needed again.

Faster to access than RAM · volatile

Which is doing the job?

A small real-world detail about ROM

Modern startup firmware is often held in rewritable flash memory and can receive a deliberate update. It is not edited like RAM during everyday work. For this lesson, remember ROM’s startup role and that it keeps its contents without power.

03 / Make room · 8 minutes

More apps than space?

Virtual memory uses an area of secondary storage to hold data moved out of RAM when space is needed. When needed again, that data is brought back into RAM. These transfers are slower than using RAM alone.

Use Browser → Photo editor → Game → Browser. Watch data move when RAM is full. Then change to 8 GB and try again.

RAM · working space

2 GB reserved here for the operating system.

Virtual memory area on the SSD

Temporary overflow, not your saved documents.

Model sizes only: each app uses two 1 GB blocks. Real systems move smaller chunks and app sizes vary. New apps load from their saved program files; returning apps may need their working data brought back from virtual memory.

Does virtual memory save my work?

No. It is managed as temporary working data, not a saved document you can rely on after restart. You still need to save. Virtual memory can help a system keep working when RAM is full, but it is not unlimited and does not make storage as fast as RAM.

04 / Three storage families · 7 minutes

Different ways to keep data.

Secondary storage keeps programs and files for later use, including when power is off. It can be built into a device or connected externally. Choose a device to explore.

Durability: resisting physical damage. Reliability: working correctly and keeping data available over time. No storage device is guaranteed never to fail.

Teacher notes, sources & saved work

One combined introductory session, approximately 50 minutes. The capacity activity is a short extension; use it for revision if time is tight. Sections 1–5 cover the main learning. Activity ticks indicate a successful check in a section, not complete mastery.

Based on Raspberry Pi “Lesson 5 Memory”, “Lessons 6 and 7 Secondary storage”, and T3/T4 worksheets, homework and answers. The source files are unchanged. Aligned with OCR J277 1.2.1 and 1.2.2, with a light introduction to capacity from 1.2.3 and a cache recap from earlier CPU lessons.

We do not equate all primary storage with volatile memory. ROM’s startup role is distinct from the operating system on secondary storage. Virtual memory can use an SSD or HDD; it is not a saved copy of a document. Sizes and transfers in the simulations are teaching models, not hardware benchmarks. Device comparisons are general tendencies; actual capacity, price, reliability and speed depend on the product and use.
